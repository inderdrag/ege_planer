# Финиш — планировщик подготовки к ЕГЭ

Веб-приложение, которое строит недельный план подготовки к ЕГЭ по реальным
номерам заданий, подстраивается под то, что у тебя получается хуже всего,
и показывает, сколько баллов не хватает до цели.

> Добавь сюда 2-3 скриншота после первого запуска — `![План недели](screenshots/plan.png)`.
> Папки `screenshots/` в репозитории ещё нет, создай её сама(м) рядом с `index.html`.

## Что умеет

- **План по реальным заданиям ЕГЭ** — математика (20 номеров), русский язык (27),
  физика (26), информатика (27) с настоящими темами, а не абстрактными «слабо/средне/сильно».
- **Один день — одно задание**, с повторами: слабые темы выпадают чаще.
  Набор заданий меняется от недели к неделе (детерминированно — одна и та же
  неделя всегда даёт один и тот же план).
- **Часы в неделю** — ты задаёшь суммарный бюджет времени, а дальше алгоритм сам
  решает, сколько минут отдать каждой теме.
- **Автоматический уровень усвоения** — после занятия отмечаешь, сколько задач
  решил и сколько верно; уровень «слабо/средне/сильно» пересчитывается сам по
  последним попыткам (чем свежее результат, тем больше у него вес).
- **Выходные и болезнь** — отметил день, и его задание переехало на ближайший
  свободный день.
- **Таймер занятия (помодоро)** — настоящее отработанное время идёт в статистику,
  а не просто галочка «сделано».
- **Пробники** — баллы по пробным ЕГЭ со временем складываются в график до цели.
- **Шпаргалки** — вкладка с шаблонами решений (пока заполнена для информатики,
  структура готова под остальные предметы).
- **Экспорт/импорт** данных в JSON-файл — прогресс не привязан намертво к одному браузеру.
- Тёмная авторская тема без UI-библиотек: чистые HTML/CSS/JS, ни одного фреймворка.

## Технологии

Vanilla JS (ES2017+), CSS Grid/Flexbox, `localStorage`. Без сборки, без npm,
без зависимостей — открывается прямо как файл.

```
ege-planner/
├── index.html
├── README.md
├── css/
│   └── style.css
└── js/
    ├── data.js       — модель данных, хранилище, нормализация
    ├── dates.js       — работа с датами и неделями
    ├── schedule.js    — алгоритм составления расписания
    ├── render.js       — отрисовка интерфейса
    ├── templates.js   — шпаргалки/шаблоны по предметам
    └── app.js          — обработчики событий, таймер, экспорт/импорт
```

## Запуск локально

Никакой установки не требуется — просто открой `index.html` в браузере.

Если решишь разбить `js/` на ES-модули в будущем — тогда понадобится локальный
сервер (`python3 -m http.server` или расширение Live Server в VS Code), потому
что `<script type="module">` не грузится напрямую с `file://`. Сейчас это не
нужно: все скрипты — обычные `<script>`-теги.

## Установка на телефон и компьютер (PWA)

Приложение — полноценный PWA (Progressive Web App): манифест, иконки и
service worker уже встроены. Это значит, что с **опубликованной** версии
(см. «Публикация на GitHub Pages» ниже) его можно поставить как обычное
приложение — без магазинов и установщиков:

- **Телефон (Android, Chrome)** — открой ссылку на GitHub Pages, в меню
  браузера выбери «Добавить на главный экран» / «Установить приложение».
  Появится иконка, как у обычного приложения, и оно будет работать офлайн.
- **Телефон (iPhone, Safari)** — кнопка «Поделиться» → «На экран «Домой»».
- **Компьютер (Chrome/Edge)** — в адресной строке справа появится значок
  установки (⊕ или монитор со стрелкой). Нажми — приложение откроется в
  своём окне, без адресной строки, и будет в списке программ/в меню Пуск,
  как обычное приложение.

Важно: service worker требует http(s) — если просто открыть `index.html`
двойным кликом (`file://`), браузер его не зарегистрирует, офлайн-режим и
кнопка установки будут недоступны. Сначала опубликуй (следующий раздел),
потом открой уже по ссылке.

## .exe для Windows — собирается сам на GitHub

Не нужно ставить Node.js и ничего собирать руками. В репозитории есть
`.github/workflows/build-windows.yml` — как только ты запушишь код на
GitHub (разделом ниже), GitHub сам, на своих серверах, соберёт `.exe` и
выложит его в разделе **Releases** твоего репозитория.

**Как это выглядит для тебя и для тех, кому скинешь ссылку:**

1. Зайди в репозиторий на github.com.
2. Открой вкладку **Actions** вверху — должен идти (или уже закончиться,
   зелёной галочкой) процесс «Собрать Windows-приложение». Первый раз после
   публикации занимает 3-5 минут.
3. Когда готово — открой **Releases** (ссылка справа на главной странице
   репозитория, или `https://github.com/<твой-ник>/ege-planner/releases`).
4. Там будет два файла:
   - **`...Setup....exe`** — обычный установщик, после него на рабочем столе
     появится ярлык;
   - **`...Portable....exe`** (или без `Setup` в имени) — просто запускаемый
     файл, ничего ставить не надо.

Это и есть «одно приложение», которое люди просто скачивают — ссылку на
Releases можно кидать куда угодно, Node.js и командная строка им не нужны.

> Windows Defender SmartScreen может показать «Windows защитила ваш
> компьютер» при первом запуске — это нормально для любого неподписанного
> независимого приложения (цифровая подпись стоит денег и тут не настроена).
> Нужно нажать **«Подробнее» → «Выполнить в любом случае»**.

Пересобирать вручную не нужно — просто пуш в `main` каждый раз запускает
сборку заново (например, через `git push` или обычный коммит в GitHub
Desktop с последующим «Push origin»). Исходники для ручной сборки на своём
компьютере (`desktop/` + `npm run build:win`) тоже остались — вдруг пригодится.

## Публикация на GitHub Pages

1. Создай репозиторий на GitHub и запушь туда содержимое этой папки:
   ```bash
   git init
   git add .
   git commit -m "ЕГЭ-планировщик"
   git branch -M main
   git remote add origin https://github.com/<твой-ник>/ege-planner.git
   git push -u origin main
   ```
2. В репозитории зайди в **Settings → Pages**.
3. В разделе **Build and deployment** выбери источник **Deploy from a branch**,
   ветку `main` и папку `/ (root)`.
4. Сохрани — через минуту-две GitHub покажет ссылку вида
   `https://<твой-ник>.github.io/ege-planner/`.

Больше ничего настраивать не нужно — проект статический, сборка не требуется.

## Известные ограничения

- Все данные живут в `localStorage` конкретного браузера. Используй «Экспорт
  данных», если садишься за другой компьютер или хочешь сделать резервную копию.
- Задания по умолчанию — реальные номера ЕГЭ, но уровни усвоения расставлены
  условно для примера; поправь их под себя (или дай приложению посчитать
  самому после нескольких занятий).
- Шпаргалки пока в основном про информатику — структура общая на все
  предметы, наполнение остальных можно дописывать по мере появления материалов.
